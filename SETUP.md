# Spider — Setup

Spider gates access behind **Discord login** and gives each user **20 generation
credits**. This guide gets both the website login and the Discord bot running.

## 1. Create a Discord application

1. Go to <https://discord.com/developers/applications> and click **New Application**. Name it "Spider".
2. **OAuth2 → General**
   - Copy the **Client ID** and **Client Secret**.
   - Under **Redirects**, add: `http://localhost:3000/auth/callback`
     (use your real domain in production, e.g. `https://yourdomain.com/auth/callback`).
3. **Bot** (only needed for the Discord bot)
   - Click **Add Bot**, then **Reset Token** and copy the **Bot Token**.
   - Invite the bot to your server: **OAuth2 → URL Generator**, scope `bot` +
     `applications.commands`, then open the generated URL.

## 2. Configure environment variables

Copy `.env.example` to `.env` and fill it in:

```bash
cp .env.example .env
# then edit .env
```

```bash
# Web login (required for the site)
DISCORD_CLIENT_ID=your_client_id
DISCORD_CLIENT_SECRET=your_client_secret
DISCORD_REDIRECT_URI=http://localhost:3000/auth/callback
SESSION_SECRET=run_to_generate            # any long random string

# Discord bot (required only for `npm run bot`)
DISCORD_BOT_TOKEN=your_bot_token
ADMIN_IDS=your_discord_user_id            # comma-separated; who can grant credits
PUBLIC_URL=http://localhost:3000          # where the site is hosted
```

Generate a strong `SESSION_SECRET` with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> **How `.env` gets loaded:** the start scripts don't auto-read `.env`. Either
> load it with Node's built-in flag — `node --env-file=.env server/index.js`
> (Node 20+) — or set the vars in your shell / host dashboard. On a host like
> Render or Railway you paste them into the dashboard instead of using a file.

## 3. Run locally

```bash
npm install
node --env-file=.env server/index.js   # web server on http://localhost:3000
node --env-file=.env server/bot.js      # (separate terminal) the Discord bot
```

Open <http://localhost:3000> — you'll see the **Log in with Discord** gate.
After logging in, the onboarding intro explains the flow, and you start with
**20 credits** (1 spent per successful generation).

## 4. Deploy as a real public website

You need a public **HTTPS** URL so Discord can redirect back and cookies stick.
The repo includes a `render.yaml` (Render Blueprint) and a `Procfile` (Railway/
Heroku-style) to make this easy.

### Render (free tier, recommended)

1. Push this repo to GitHub.
2. On <https://render.com>: **New → Blueprint**, pick the repo. It reads
   `render.yaml` and creates a **web** service (and optionally the **bot** worker).
3. After the first deploy you get a URL like `https://spider-web.onrender.com`.
   Set these in the service's **Environment** tab:
   - `DISCORD_REDIRECT_URI = https://spider-web.onrender.com/auth/callback`
   - `PUBLIC_URL = https://spider-web.onrender.com`
   - `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` (from step 1)
   - `SESSION_SECRET` is auto-generated by the blueprint.
   - For the bot worker: `DISCORD_BOT_TOKEN`, `ADMIN_IDS`.
4. Back in the **Discord app → OAuth2 → Redirects**, add that exact
   `https://.../auth/callback` URL.
5. Redeploy. Visit your URL — login now works for anyone.

### Railway (alternative)

1. Push to GitHub, then on <https://railway.app>: **New Project → Deploy from
   repo**. Railway runs `npm start` via the `Procfile`.
2. Add a second service from the same repo with the start command `npm run bot`
   for the Discord bot.
3. In each service's **Variables**, add the same env vars as above, using your
   Railway-provided `https://...up.railway.app` domain for `DISCORD_REDIRECT_URI`
   and `PUBLIC_URL`. Add the redirect URL to the Discord app too.

> Set `NODE_ENV=production` (the blueprint does this) so the session cookie is
> marked `Secure`. The app binds `process.env.PORT` automatically.

### ⚠ Credit persistence on free hosts

Credits live in `data/users.json` on the local disk. Render/Railway **free**
tiers have *ephemeral* disks — that file resets on every redeploy/restart, so
everyone's credits go back to 20. To keep credits permanently, attach a
persistent disk/volume mounted at `data/` (Render: add a Disk with mount path
`/opt/render/project/src/data`; Railway: add a Volume mounted at `.../data`), or
move the store to a database. For testing, the ephemeral default is fine.

## Credits

- Each user starts with **20**. A credit is spent per successful generation
  (website chat *or* the in-Studio plugin chat — they share one pool).
- Stored in `data/users.json` (created automatically; safe to back up).
- Admins manage credits from Discord:
  - `/credits check @user`
  - `/credits grant @user 20`
  - `/credits set @user 100`
  - `/credits reset @user`   (back to 20)
  - Users check their own with `/mycredits`, or DM the bot for a login link.

## Notes

- If Discord creds are missing, the site shows a "login not configured" notice
  and the API refuses generation — set the env vars above to enable it.
- For production, serve over HTTPS and set `DISCORD_REDIRECT_URI` / `PUBLIC_URL`
  to your real domain. The session cookie is `HttpOnly; SameSite=Lax`.
